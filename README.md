## 자바 웹(2) 포토폴리오 만들기 프로젝트 ##

## 1. 프로젝트 소개

자바 웹 수업에서 배운 내용을 바탕으로 웹 페이지를 만들고 회원 관리 기능을 구현했다. 처음에는 화면에 데이터를 출력하는 것부터 시작했고, 이후 데이터베이스 연결, 회원가입과 로그인, 권한 관리, REST API까지 순서대로 실습했다.

주차별로 새로운 기능을 추가하면서 앞에서 배운 내용이 다음 기능과 어떻게 연결되는지 알 수 있었다. 기능을 직접 구현하는 과정에서 오류도 여러 번 발생했는데, 코드를 확인하고 테스트하면서 원인을 찾아 수정하는 경험을 할 수 있었다.

## 2. 주차별 실습 내용 

2주차 - Model을 이용한 데이터 전달

Model에 데이터를 담아 HTML 화면에 전달하고 출력하는 방법을 배웠다. 컨트롤러에서 데이터를 전달하면 화면에서 해당 값을 사용할 수 있다는 것을 실습했다.

처음에는 Java 코드와 HTML 화면이 어떤 방식으로 연결되는지 익숙하지 않았지만, 데이터를 전달하고 화면에 출력되는 결과를 확인하면서 기본적인 동작 방식을 이해할 수 있었다.

## 3주차 - 포트폴리오 페이지 제작

포트폴리오 페이지를 만들고 카테고리별로 내용을 나누어 배치했다. 아이콘과 링크를 연결하고 Bootstrap 5를 활용해 화면을 구성했다.

기능을 만드는 것뿐 아니라 화면의 배치나 디자인도 중요하다는 것을 느꼈다. 같은 내용이라도 어떻게 배치하느냐에 따라 보기 편한 정도가 달라졌고, 사용자가 쉽게 확인할 수 있도록 구성하는 것도 필요하다는 것을 알게 되었다.

## 4주차 - 데이터베이스 연동

데이터베이스와 웹 프로젝트를 연결하고 TestDB에 저장된 데이터를 조회하는 실습을 진행했다. 프로젝트에서 Controller, Service, Repository가 각각 어떤 역할을 하는지도 살펴보았다.

데이터베이스에 저장된 내용을 웹 화면에 표시하려면 데이터를 조회하고 전달하는 과정이 필요했다. 화면에 보이는 결과만 확인하는 것이 아니라, 데이터가 어디에서 가져와지고 어떤 코드를 거쳐 전달되는지도 확인하게 되었다.

## 5주차 - 회원가입과 로그인

회원가입과 로그인, 로그아웃 기능을 구현하고 Spring Security를 적용했다. 회원 정보는 데이터베이스에 저장하고, 비밀번호는 BCrypt를 이용해 암호화하도록 했다.

회원가입 과정에서는 사용자가 입력한 정보가 서버로 전달되고 저장되는 흐름을 확인했다. 비밀번호를 그대로 저장하는 것이 아니라 암호화해서 저장해야 한다는 점도 배웠다.

로그인 기능을 구현하면서 보안 설정에 따라 접근할 수 있는 페이지가 달라진다는 점을 알게 되었다. 단순히 로그인이 되는지만 확인하는 것이 아니라, 사용자의 정보를 안전하게 관리하는 것도 중요하다고 느꼈다.

## 6주차 - 회원 권한 관리

회원의 권한을 구분하고 관리자 페이지에 접근할 수 있는 권한을 설정했다. USER와 ADMIN 등의 권한에 따라 페이지 접근 결과가 달라지는지 확인했다.

처음에는 로그인을 했다면 페이지에 접근할 수 있을 것이라고 생각했지만, 실제로는 로그인 여부와 권한에 따라 접근 결과가 달라졌다. 관리자 권한이 없는 계정으로 관리자 페이지에 접근했을 때 차단되는 것도 확인했다.

이 실습을 통해 화면에서 메뉴를 보이지 않게 만드는 것만으로는 충분하지 않고, 서버에서도 권한을 확인해야 한다는 것을 배웠다.

## 7주차 - REST API와 JSON

7주차에는 회원 관리 기능을 REST API로 구현하고 Postman으로 테스트했다. 회원 목록과 개별 회원을 조회하고, 회원을 등록하거나 권한을 변경하고 삭제하는 요청을 확인했다.

HTTP 메서드에 따라 요청하는 작업이 달라진다는 점을 배웠고, 요청 결과를 상태 코드와 JSON 응답으로 확인하는 방법도 익혔다.

추가로 회원 아이디와 이름에 검색어가 포함된 회원만 조회하도록 검색 기능을 구현했다. 검색어를 입력했는데도 전체 회원이 조회되는 문제가 있었는데, 코드를 다시 확인해 보니 컨트롤러에서 전체 조회 메서드를 사용하고 있었다. 검색 메서드를 연결한 뒤 Postman에서 아이디 검색, 이름 검색, 검색 결과가 없는 경우를 각각 테스트해 해결했다.

예외 처리도 개선했다. 기능마다 오류를 처리하는 코드가 반복되는 부분을 줄이기 위해 @RestControllerAdvice를 사용하는 GlobalExceptionHandler를 만들었다. 비밀번호 확인이 일치하지 않거나 잘못된 권한을 전달하는 경우, 존재하지 않는 회원을 삭제하려는 경우 등을 테스트하고 오류 메시지가 JSON으로 반환되는지 확인했다.

## 3. 문제 해결 과정

수업을 따라 실습할 때는 교수님의 설명과 예제 코드를 보면서 기능을 구현할 수 있었지만, 연습문제에서는 배운 내용을 직접 적용해야 해서 어려움이 있었다. 예제에 나온 코드를 그대로 작성하는 것과 필요한 부분을 찾아 수정하는 것은 다르다는 것을 느꼈다.

특히 7주차 검색 API를 구현할 때 검색어를 전달했는데도 전체 회원이 조회되는 문제가 있었다. 처음에는 검색 조건에 문제가 있는 줄 알았지만, 코드를 다시 확인하면서 컨트롤러가 검색 메서드가 아닌 전체 조회 메서드를 호출하고 있다는 것을 찾았다. 호출하는 메서드를 수정하고 여러 검색어로 다시 테스트하면서 문제를 해결했다.

Postman을 사용하면서는 요청 주소뿐 아니라 요청 방식도 정확하게 설정해야 한다는 것을 알게 되었다. GET이나 PATCH처럼 메서드가 달라지면 같은 주소라도 처리 결과가 달라질 수 있었다. 요청을 보낸 뒤에는 응답 상태 코드와 본문을 함께 확인하면서 문제가 요청에 있는지, 서버 처리에 있는지 살펴보았다.

예외 처리 부분에서는 잘못된 요청이 들어왔을 때도 결과를 확인할 수 있도록 공통 처리 클래스를 작성했다. 잘못된 권한을 전달하거나 회원 삭제에 실패하는 경우 등을 테스트하면서 정상적인 요청뿐 아니라 잘못된 요청도 확인해야 한다는 것을 배웠다.

이러한 과정을 거치면서 오류가 발생했을 때 무작정 코드를 수정하기보다는 먼저 관련 코드를 확인하고, 원인을 찾은 다음 수정한 내용을 다시 테스트하는 것이 중요하다는 것을 느꼈다.

## 4. 느낀 점

수업 시간에 교수님과 함께 프로젝트를 만들 때는 강의 순서에 따라 진행하면 큰 어려움 없이 기능을 구현할 수 있었다. 하지만 주차별 연습문제를 풀 때는 배운 내용을 직접 활용해야 해서 생각보다 어려웠다. 예제 코드를 보고 따라 작성할 때는 이해했다고 생각했는데, 막상 비슷한 기능을 혼자 구현하려고 하니 어떤 코드를 사용해야 하는지, 어디를 수정해야 하는지 바로 떠오르지 않는 경우가 있었다.

특히 회원 검색 API를 만들면서 검색어를 전달하는 것만으로 기능이 완성되는 것이 아니라, 컨트롤러와 서비스, 리포지토리가 제대로 연결되어 있어야 한다는 것을 알게 되었다. 기능 하나를 만들더라도 여러 부분이 함께 동작하기 때문에 코드의 역할과 연결 관계를 이해하는 것이 중요하다고 느꼈다.

또한 로그인과 권한 관리, 비밀번호 암호화를 실습하면서 웹 기능은 정상적으로 동작하는 것뿐 아니라 보안도 고려해야 한다는 것을 배웠다. REST API를 구현한 뒤에는 Postman으로 요청을 직접 보내면서 응답 결과를 확인하는 방법도 익힐 수 있었다.

아직 코드를 처음부터 혼자 작성하는 데 익숙하지 않은 부분이 있다. 그래도 오류가 발생했을 때 코드를 다시 살펴보고, 원인을 찾아 수정한 뒤 결과를 확인하는 과정을 반복하면서 조금씩 익숙해지고 있다. 앞으로는 예제 코드를 그대로 따라 하는 데 그치지 않고, 각 코드가 어떤 역할을 하는지 이해하면서 직접 작성하는 연습을 더 하고 싶다.
